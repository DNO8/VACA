# SWE-1.7 Implementation Backlog

## Execution contract

Execute work units in order. Keep tests, migrations, runtime verification, and user-facing documentation with the behavior they validate. Preserve unrelated user changes. Do not commit secrets, use debug signing for release artifacts, or claim external store publication without portal evidence.

When a required external credential or legal decision is unavailable:

1. Complete all implementation that does not require the secret.
2. Keep production behavior fail-closed.
3. Add deterministic configuration and verification instructions.
4. Report one exact blocker with owner and required value.
5. Do not substitute mock credentials in release builds.

## Delivery strategy

This implementation is too large for one reviewable change. Organize it as the following independent work units or chained PR slices. Each slice must build and retain coherent behavior.

| Slice | Outcome |
| --- | --- |
| A | Cross-platform foundation and new incident domain |
| B | Secure public offline incident experience |
| C | Backend contract and authenticated Internet delivery |
| D | Android municipal BLE DTN pilot |
| E | Store readiness, hardening, and release evidence |

If commits are requested, use Conventional Commits without AI attribution. Do not force-push.

## Slice A — Cross-platform foundation and incident domain

### A1 — Baseline and environment verification

**Goal:** establish a reproducible baseline without changing product behavior.

**Actions**

- Inspect repository status and preserve pre-existing changes.
- Verify installed Flutter/Dart versions against `pubspec.yaml`.
- Run dependency resolution, code generation, analysis, and existing tests.
- Record pre-existing failures separately from introduced failures.
- Inspect all current dependencies before adding a library.
- Verify current official Flutter, Android, Apple, and selected package documentation.

**Acceptance**

- Baseline commands and exact results recorded.
- No source mutation from formatters remains unreviewed.
- Existing generated Drift code is reproducible.

**Verification**

```text
flutter doctor -v
flutter pub get
dart run build_runner build --delete-conflicting-outputs
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
```

**Rollback boundary:** no product files should change except deterministic generated files proven necessary.

**Goal:** make the public Flutter project structurally cross-platform.

**Actions**

- Add camera and location-when-in-use descriptions with approved neutral placeholder copy clearly marked for legal/product review.
- Do not add iOS BLE relay capability.
- Add required privacy manifest structure according to current Apple requirements and actual dependencies.

**Acceptance**

- Flutter recognizes Android and iOS targets.
- Public iOS source contains no municipal gateway or BLE relay UI.

**Verification**

**Rollback boundary:** generated `ios/` foundation and platform-specific configuration only.

**Acceptance**

## Slice C — Backend contract and authenticated Internet delivery

### C1 — Define and implement canonical bundle codec

**Goal:** create the stable transport object shared by Internet and BLE.

**Actions**

- Implement fields and rules from `02-hybrid-dtn-architecture.md`.
- Use deterministic compact encoding with strict size/depth/fragment limits.
- Separate `expiresAt` and `hopLimit`.
- Sign protected header plus ciphertext hash.
- Version the codec.
- Add fuzz/property tests where supported.

**Acceptance**

- Encoding is deterministic.
- Unknown incompatible versions are rejected.
- Oversized and malformed bundles fail before dangerous allocation.
- Ciphertext contains no recoverable plaintext in serialization tests.

**Focused tests**

- Known fixture round-trip.
- Determinism.
- Truncation/malformed input.
- Tampered header/payload.
- Expiration/hop limit.
- Fragment bounds.

**Rollback boundary:** bundle codec and protocol records.

### C2 — Implement origin outbox and scheduler

**Goal:** replace the entity-upsert queue with durable bundle delivery.

**Actions**

- Add origin bundle, attempts, receipts, and tombstone persistence.
- Implement priority plus age scheduling.
- Add bounded retry/backoff/jitter.
- Recover from process death.
- Prevent P5 from blocking P0–P4.
- Reconcile duplicate link attempts by message ID.

**Acceptance**

- Process restart preserves queue and retry state.
- Expired bundles stop transmitting.
- P0/P1 preempt queued media while fairness/aging remains tested.
- Verified receipt closes origin delivery idempotently.

**Rollback boundary:** DTN outbox/scheduler persistence.

### C3 — Implement authorized server contract

**Goal:** provide a deployable reference contract for incident ingestion and receipts.

**Actions**

- Use Supabase Postgres, private Storage, and Edge Functions as the reference backend.
- Add a `supabase/` project layout with versioned schema migrations for opaque identities, incidents, events, attachments, idempotency, and receipts.
- Implement Edge Functions for bundle ingestion, private attachment authorization, account-deletion requests, and the KYC webhook boundary.
- Implement authenticated ingestion, strict validation, dedupe, update/cancel semantics, and signed receipt response.
- Add row/role authorization and cross-user isolation tests.
- Implement the Didit webhook only from current official provider documentation.
- Keep service-role credentials, KYC webhook secret, and server receipt-signing private key in Supabase environment secrets, outside the repository.

**Acceptance**

- Duplicate message ID/payload hash returns the same logical acceptance.
- Conflicting duplicate is rejected and audited.
- Unauthorized cross-user reads/writes fail.
- Receipt verifies in mobile tests.
- Production deployment instructions identify external credentials without embedding them.

**Focused tests**

- Authenticated create/update/cancel.
- Idempotent retry.
- Conflicting duplicate.
- Oversized body/media rejection.
- KYC webhook signature and replay rejection.
- Receipt signature verification fixture.
- Authorization isolation.

**Rollback boundary:** backend migrations/functions/reference implementation.

### C4 — Implement Internet link adapter

**Goal:** deliver bundles reliably over HTTPS.

**Actions**

- Replace placeholder `InternetTransport.send` behavior.
- Detect authorized endpoint reachability, not only network interface presence.
- Upload idempotent batches.
- Upload media independently and resumably when supported.
- Verify receipts before updating UI state.
- Handle captive portal, timeout, retryable server error, auth expiry, and conflict.

**Acceptance**

- Offline create later reaches server.
- Repeated reconnect loops create one incident.
- Invalid receipt does not close delivery.
- Logs remain redacted.

**Runtime scenario:** airplane mode → create → restart → reconnect → server receipt; record exact result.

**Rollback boundary:** Internet adapter and sync orchestration.

**Actions**

- Add gateway capacity slots, jitter, hysteresis, and per-peer quotas.
- Upload through authorized HTTPS contract.

**Acceptance**

- Three-device physical scenario passes.
- Origin can leave after relay custody.
- Fake/expired gateway beacon is rejected.
- Multiple delivery paths create one server incident.
- Gateway cannot decrypt incident payload.
- Signed receipt reaches/reconciles with origin when a path becomes available.

**Runtime scenario:** record topology, devices, Android versions, bundle IDs, timestamps, battery observations, and server receipt evidence without sensitive payloads.

**Rollback boundary:** multi-hop routing and gateway mode.
