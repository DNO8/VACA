## Superseded concepts

The following concepts are retired from the active VACA product model. They may remain only in explicitly historical or contractual records.

Do not implement:

- FIBE branding, form, modules, official codes, or citizen “official assessment”.
- RUT hash as the primary application identity.
- Aid eligibility or government benefit determination.
- Stellar-based aid distribution, Claimable Balances, Social Yield, tokenization, or Proof of Aid. The only approved Stellar scope is the optional isolated testnet wallet defined below.
- Automatic emergency-resource or drone dispatch.
- Wi-Fi Direct/Aware, LoRa, satellite, MQTT, or custom QUIC for this release.
- iOS BLE relay.
- Public gateway mode.

Preserve historical/reference documents unless a task explicitly requires updating an active source reference. Do not delete user-provided assets or unrelated work.

## Fixed product decisions

- Public app platforms: Android and iOS.
- Public transport: durable offline outbox + HTTPS synchronization.
- Municipal pilot transport: Android custom BLE DTN relay, not Bluetooth SIG Mesh.
- BLE pilot is disabled in public builds.
- BLE carries compact encrypted signals; full media is deferred to Internet.
- KYC is preparation and identity assurance, not incident truth.
- Unverified users may save P0/P1 signals.
- Relay devices and gateways cannot decrypt incident payloads.
- Server delivery requires a verified signed receipt.
- Institutional acknowledgment is separate from server receipt.
- Visual direction: Celadon Civic Classicism, sober operational UI.
- User-facing copy: neutral professional Spanish.
- Source identifiers, protocols, and new technical documentation: English.
- The optional Stellar wallet is testnet-only, independently navigated, and never carries incident data or affects identity assurance, delivery priority, eligibility, or aid decisions.

```text
first run

  P1 → unverified profile → P5 → P6 → P7 → P8 → P9

  P4 → P5 → P6 → P7 → P8 → atomic local save → P9

secondary destinations
  P4 → P10 | P13

  P4 → P10 → P12
```

The public shell exposes Home, Delivery, and Identity/Data as stable destinations. Capture remains the dominant action. P14 is reachable only from Identity/Data and has no deep link into incident creation or delivery.

### State ownership

| State | Authority |
| --- | --- |
| First-run and accepted consent version | Local identity profile plus protected app setting. |
| Identity assurance and opaque credential | Drift `IdentityProfiles`; secret device material in platform secure storage. |
| In-progress capture | One Flutter controller scoped to the capture route; no placeholder global values. |

| Connectivity and delivery progress | `Transport`/scheduler streams projected from persisted delivery state. |
| Stellar public account and testnet network | Wallet service; secret seed only in platform secure storage, never Drift or logs. |

## Security constraints

- Never commit or print secrets.
- Never store raw RUT, identity document, biometrics, complete KYC response, or provider secret in the app.
- Never log exact coordinates, plaintext notes, media paths, credentials, keys, or serialized encrypted bundles.
- Do not implement cryptographic primitives manually.
- Select maintained reviewed libraries and add tamper/known-fixture/round-trip tests.
- Use strict protocol size, fragment, retry, storage, peer, and copy-budget limits.
- Validate cheap header bounds before expensive work or allocation.
- Production builds fail closed when trust roots or endpoints are missing.
- A local save, relay custody, gateway custody, server receipt, and institutional acknowledgment are distinct states.

## Implementation method

Execute `04-swe-1.7-implementation-backlog.md` in order. For each work unit:

1. Mark the work unit in progress.
2. Read affected source and adjacent conventions.
3. Add or update tests with the behavior.
4. Implement the smallest coherent change.
5. Run focused verification.
6. Run the runtime scenario or record a typed unavailable result.
7. Record exact results and rollback boundary.
8. Continue to the next non-blocked unit.

Do not stop at the first missing external credential. Complete all code/test/configuration work that can be verified with development trust roots and mocks, while ensuring release flavors reject mock configuration.

Do not create commits unless the invoking user or automation explicitly requests them. If commits are requested, use Conventional Commits, keep tests with behavior, and add no AI attribution.
